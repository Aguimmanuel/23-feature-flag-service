# Database Schema

PostgreSQL 18 stores three application tables. [SQLAlchemy models](../backend/app/models.py) define the mapping; [Alembic revision `0001`](../backend/migrations/versions/0001_initial_schema.py) creates the schema. Follow the [README](../README.md) for setup and migration commands.

```text
flags (one) ──────< flag_environments (three per flag)
  └──────────────< audit_logs (many per flag)
```

| Table | Main fields | Purpose |
| --- | --- | --- |
| `flags` | `id` UUID primary key; unique `key`; `description`; `archived`; `created_at`, `updated_at` | Feature identity and lifecycle. |
| `flag_environments` | Composite primary key (`flag_id`, `environment`); `enabled`; `target_groups` TEXT[]; `rollout_percentage`; `version`; `updated_at` | Independent development, staging and production settings. |
| `audit_logs` | `id` UUID primary key; `flag_id`; nullable `environment`; `action`; `actor`; `before_state`, `after_state` JSONB; `created_at` | Before/after history of successful changes. |

The composite primary key means each flag can have only one row for each environment. For example, `(flag-A, staging)` and `(flag-A, production)` are separate configurations, but a second `(flag-A, staging)` is rejected.

Both child tables reference `flags.id` with `ON DELETE RESTRICT`: a child must reference an existing flag, and the database blocks physical deletion of a flag while child rows exist. UUIDs are generated by application code; timestamps are timezone-aware. There is no users, group-membership or credentials table.

## Important rules

- **Creation:** one transaction creates a flag, three disabled environment configurations (empty groups, 0%, version 1) and a creation audit event. The application enforces the three-row invariant.
- **Database constraints:** valid key format, unique keys, allowed environments, percentage 0–100, version ≥1, at most 20 group-array elements, no null elements and a one-dimensional array when nonempty. The API additionally validates group lengths, uniqueness and whitespace.
- **Concurrency:** updates lock the parent flag. Configuration PUT also checks the submitted version, then increments it. For example, saving version 1 produces version 2; another request still using version 1 fails with 409. Versions belong to individual environment configurations, not the whole flag.
- **Atomic history:** the business change and audit event commit together. Audit failure rolls back the change.
- **Archival:** sets `archived=true`; rows/history remain and the key cannot be reused. There is no restore or permanent-delete API.
- **Audit:** flag actions use null environment; configuration updates specify one. Creation has null `before_state`; `after_state` is required. JSONB stores structured snapshots, not complete request headers or credentials. The API exposes them as `before` and `after`. Failed changes and evaluation requests add no audit entry.
- **Timestamps:** application code updates `updated_at`; there is no automatic database update trigger.

The unique key index supports lookups. The environment primary key supports configuration reads. Audit history uses `(flag_id, created_at DESC, id DESC)` for newest-first retrieval. Evaluation reads the requested configuration with one join and writes no audit event.

Optional seed creates `new-checkout` and `search-preview` with actor `seed`. Existing keys—including archived keys—are skipped without resetting saved data. Runtime audit actor is `shared-admin`; history is not individual-user attribution or protection against database administrators.

Use migrations for schema changes, not manual table creation. Keep destructive tests on the separate local disposable test database, never the hosted database. Credentials remain in private backend configuration.
